安装 `engine-lock.json` 中的 Godot 及 Python 3；导出另需匹配的官方模板。在仓库根目录执行：

```sh
python3 tools/migration/prepare_sample_assets.py
python3 tools/migration/check_godot.py
./play                            # 首页确认出发后进入已集成首关
./play --test level               # 开发时直达首关
./play --test boss --mana 0        # 同一首关中的索尔专项
godot --editor --path godot        # 打开编辑器
```

资源转换保留既有图像、脚点、锚点和帧缩放；重复运行结果一致。规则检查包含旧版 55 个场景／4,250 次公开状态对比，以及小样、输入适配和布局保存重开检查。参照回放容许 0.001 世界单位数值误差；角度按同方向比较。自动检查不代表原生操作、性能或双平台验收通过。

操作：WASD 移动，鼠标独立瞄准，左键点按／按住射箭，Q 穿透箭，E 箭雨，G 回风，T 蓄势，C 神兽技（引风），空格闪避，F 互动／过门／安全营地整理，B 开关背包（安全营地内可整理，战斗／探索中仅查看；在营地内选中物品按 R 旋转），Tab 3秒拾取卡内快捷转坛，V 使用已绑定器，X 点燃祭坛显灵容器，M 地图总览，Esc 暂停／合上残碑／收起背包，R 重试，F11 或右上角按钮切换全屏。失焦暂停，窗口变化取消输入但不暂停。阅读与安全营地整理停止游戏时间；完成终点后可以回头探索。

默认由 `scenes/boot.tscn` 进入原生 `scenes/home.tscn` 首页。完整征程从入口出发（首页背包整理结果会作为初始构筑带入本局）；自选起点（快速测试）选择第一关·汤谷及任意已实现房间，以所带构筑和三资源100新开独立测试局，可继续推进，但不计正式完整通关。首页与局内使用同一份正式 50 格背包（装备 `6×5`、祭坛 `4×4`、收纳 `4×1`）；游戏统一使用“背包”和“收纳区”，不提供独立仓库概念。窗口标题由启动器固定为“九鼎 · 汤谷”，正式玩家路径不显示调试状态。

编辑 `scenes/rooms/` 十六个独立房间（十三主线＋三支路）。F靠近门切房，门标明目的房与前行／返回／可选支路／汇入主路，选择门另标神兽祝福（青龙／白虎／朱雀与初念／再念／三念）并叠加独立门楣兽种浮雕与柱面念级章数纹理层（`portal_blessing_visual.gd`），运行时动态补出的选择门／返回门按 340×320 保守呈现占地留出 12 单位间隙及 >160 互动点距离；M仍为当前房总览，右上角小地图显示当前房间可行走轮廓、玩家与门的互动位置及封门／可通行状态。任务期间封门，完成可回溯且不刷新。仅入口、祭火营地、雷庭前径（或本房清庭后靠近 `CampPoint` 100 距离内无遮挡处）可按 B／F 或点击右下角 `背包 · B` 进入营地整理，整理停时且不补满资源；其余时刻按 B 为不暂停的仅查看模式。完整征程存活时R先确认，阵亡或快速测试R直接按本次起点重开；暂停／阅读／整理中R无效（营地整理中 R 用于旋转选中物品）。暂停菜单回首页先确认，取消保留原进度与暂停状态。地图编辑见[房间地图说明](../docs/guides/汤谷房间地图使用说明.md)，候选交付与原生待验见[扩展实施记录](../docs/mvp/汤谷首关扩展_实施记录_2026-10-26.md)。

保存后 F5、重新打开与导出均读取当前原生场景；生成工具只允许新路径，不覆盖编辑器修改。地图使用二维世界坐标，不额外叠加等距投影，Node.js 不参与运行。

后台检查使用 headless，不启动窗口或发送系统键鼠事件。真实窗口、画面、前台性能和稳定性待用户安排后单独验收；不以后台帧率冒充前台结果。当前证据与逐项验收清单见 [候选验收记录](../docs/migration/Godot候选_验收记录.md)。

## 低配机器与性能诊断

2026-10-26 后台性能调优已合入：缓存障碍集合、每帧只构造一次公开快照、HUD 文本一次写入、环境物件复用几何与画布逆变换、特效精灵缓冲复用；呈现改为跟随渲染帧（同帧后续物理 tick 只推进规则并累积时间，最多跳过 4 个 tick 兜底）。规则、数值、碰撞、输入中断和默认画面保持不变，详见[性能调优记录](../docs/architecture/九鼎_性能优化_2026-10-26.md)。

后台工作量回归位于 `tests/performance_checks.gd`，已纳入 `tools/migration/check_godot.py`；同机前后对比使用 `python3 tools/migration/perf_godot.py --repeat 3`。该脚本只测量 headless 规则＋快照成本，**不是原生 FPS**，前台画面、手感、60 秒跑射和 5 分钟稳定性仍需用户在目标机器验收。

需要降低低配机特效叠加时，可显式指定画质档位（默认 `high` 与已批准画面一致）：

```sh
./play --quality=auto    # 按帧时间自动在 512 / 256 / 96 个特效叠加间切换
./play --quality=low     # 固定低档
```

原生包把参数放在 `--` 之后，例如 `NineTripods.exe -- --quality=auto`。画质档位只减少非玩法关键的特效叠加，不改碰撞、伤害、冷却或规则时间。
