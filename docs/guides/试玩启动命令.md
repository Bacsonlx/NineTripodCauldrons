# 试玩启动命令

2026-10-26。本集成分支第一关为十六房扩展候选：十三主线＋三支路，主线119影偶／21波，含支路134影偶／24波；索尔援军另计，保留技能、药瓶及未入库Boss奖励占位。直接启动即可玩，不需要先启用测试环境。完整背包、正式装备奖励与未接通的白盒效果仍按原范围后续制作。

## 一条命令开始

安装 `godot/engine-lock.json` 锁定的 Godot 并加入 PATH，准备 Python 3；在仓库根目录执行：

```sh
./play
```

Windows 或不使用可执行脚本时运行 `python play`；也可用 `python3 /完整路径/十日/play` 从其他工作目录启动。命令会检查引擎版本，运行项目当前代码，不先导出原生包、不依赖 Node.js。2026-10-24 起默认先进入原生首页，选择「踏入汤谷」并确认后进入真实首关；首页仓库为试装预览，不影响战斗配置，见[实施记录](../mvp/首页与征程入口_实施记录_2026-10-24.md)。

首页左栏选择「完整征程」或「快速测试」；快速测试可选择第一关·汤谷的任意房间，以默认构筑和三资源100开始，仍可继续过门探索。Esc暂停菜单返回首页需确认，结束当前局且不保存进度。重新从首页进入不继承命令行旧资源条件。

## 选择测试内容

| 命令 | 开始位置与行为 |
| --- | --- |
| `./play` | 首页 → 出发确认 → 正常第一关：入口 → 十三主线及三可选支路 → 索尔 → 出口 |
| `./play --test level` | 绕过首页，直接进入正常首关 |
| `./play --test boss` | 第一关中的索尔雷庭，保留实际门与首关呈现 |
| `./play --test boss --health 40 --mana 0 --stamina 0` | 低生命、零蓝、零精力的 Boss 条件 |
| `./play --test drops --health 60 --mana 40 --seed 13` | 第一战斗庭，从非满资源观察即时药瓶补给 |
| `./play --test drops --room court2` | 第二庭的实际波次与掉落 |
| `./play --room court3` | 从第三庭开始，规则正常运行，不直接标为完成 |
| `./play --test alpha` | 原有背包／六器白盒；占位内容不代表正式第一关已实现 |
| `./play --test rules` | 后台公开规则回归，不打开窗口 |
| `./play --headless --quit-after 3` | 默认首页后台启动检查；3 是主循环次数，不是秒 |
| `./play --test level --headless --quit-after 3` | 首关后台启动检查 |
| `./play --dry-run` | 只显示最终命令，便于核对，不启动程序 |
| `./play --help` | 查看全部参数与范围 |

`--test boss`／`drops` 只改变开始位置，使用同一套第一关规则，药瓶始终启用。可与 `--health`、`--mana`、`--stamina`、`--seed` 组合；Boss 专项只接受 boss 房。`alpha` 和 `rules` 不接受房间、资源或掉落种子，避免看似接受却不生效。

低配机器可附加 `--quality=auto`（按帧时间自动降低特效叠加）或 `--quality=low|medium|high`；默认 `high` 保持已批准画面。画质档位只影响非玩法关键的特效数量，不改规则、碰撞或数值，详见[首轮性能调优记录](../architecture/九鼎_性能优化_2026-10-26.md)。原生包写法：`NineTripods.exe -- --quality=auto`。

房间可选 `entry`、`court1`、`dry_creek`、`root_fork`、`stele`、`court2`、`altar`、`ash_cloister`、`gate_forecourt`、`court3`、`thunder_approach`、`boss`、`end`、`moss_side`、`stele_side`、`ember_side`。生命范围 1—100，蓝量／精力范围 0—100，不指定时均为 100。所有值仅用于本次启动，不写存档或修改场景文件。

完整征程存活时R先确认；阵亡后或快速测试R直接从本次起点和初始资源重试。暂停／阅读／整理中R无效。首页快速测试可选全部16房，默认三资源100；显式 `--room=entry` 也保留测试身份。跨房正常携带局内资源，测试到出口只记片段完成。正常启动时 R 重新随机掉落；显式指定 `--seed` 时 R 重演同一种子，便于复核。指定某房间不自动清除其他房间，也不代替完整通关验证。

## 原生包与后台检查

已导出的程序默认同样先进入首页，并在确认出发后加载全部已接入首关玩法。若要直达首关或专项启动，将游戏参数放在 `--` 后面，例如：

```sh
"九鼎 · 汤谷.app/Contents/MacOS/九鼎 · 汤谷" -- --test=boss --health=40 --mana=0
"九鼎 · 汤谷.app/Contents/MacOS/九鼎 · 汤谷" -- --test=level
NineTripods.exe -- --test=drops --health=60 --mana=40 --seed=13
```

原生程序参数使用 `--名称=值`；`./play` 接受上表中的空格形式并自动转换。`rules` 仅在源码工程中由快捷命令调用。官方导出模板不支持命令行覆盖场景路径，使用上述游戏参数即可。

AI 的验证继续遵守后台限制：只执行 `--headless` 或规则检查，不自动运行无参数 `./play`，不打开原生窗口或发送系统键鼠事件。用户可自行启动前台试玩；后台结果不代表画面、手感、性能或 Windows 实机验收通过。
