# 首关 Boss：索尔原型与施工计划 v0.1

2026-10-22。状态：设计方向已确认；B01—B04已进入独立灰盒实现，具体证据见[实施记录](首关Boss_索尔_实施记录_2026-10-22.md)。以下具体数值仍为试玩初值，动画与平衡验收尚未完成。

## 1. 确认范围与完成标准

用户两轮确认：先做索尔单阶段战斗原型，核心为观察前摇、横向走位、抓收招空档射箭；形象采用异乡雷神的皮影重将；三招为近身挥锤、远程掷锤、落雷逼位；以锤离手后的破绽为独特机制。本轮交付概念图、战斗与数值设计、施工计划；可玩灰盒是下一阶段。先独立测试房，再考虑首关接入，正式流程不额外补满资源。

索尔是已确认的技术验证对象，不能据此写成正式第一局的剧情 Boss。北欧神真名档才亲自到场，地方身份及低档外观另行设计。故事、借眼、签署、正式存档、完整六器与奖励不随本原型自动实施。依据：[故事基线](../story/九鼎_故事基线_v1.2与架构影响.md)、[玩法规则](../product/十日_玩法与运行规则.md)、[架构结论](../architecture/九鼎_架构选型结论.md)。

原型要回答：三招是否清楚可辨？玩家能否主要靠走位化解威胁、在掷锤后主动反击？零蓝能否完成击败？反击窗口是否足够射出有价值的一箭？未验证前不铺完整动画。

## 2. 形象与素材合同

概念图及提示词见 [BOS-001 制作记录](../../output/art/BOS-001/2026-10-22-concept-v1/README.md)。这是视觉候选，不是已接受的动画母图或可切帧图集。

- 身份气质：疲惫、负伤但有压迫感的异乡雷神。宽肩、低重心，站立可见身体高度目标约为孩子的 2 倍；碰撞尺寸独立调校。
- 材质与色彩：暗铁甲、旧皮革、暗红布带；剪刻轮廓、关节铆接及镂空装饰承载皮影语言，少量像素质感。蓝白雷光集中在武器及前臂，伤害范围由清楚的地面标记表达。
- 识别点：方头短柄重锤、宽肩轮廓、疲惫面部；普通状态清楚看到锤，离手状态双手无锤、身体敞开。破绽使用姿态、胸前断裂纹光及 HUD 小标记共同表达。
- 镜头：沿用当前固定等距俯视。主母图确定后再制作前、后、左、右四向；维持同一身体比例和脚点，不套用动画默认方向数。
- 拆件：身体／独立重锤／雷电特效。脚点为身体地面根，锤有握点及飞行中心。动作位移由规则计算，画面不能改变碰撞或伤害时点。
- 动作最小集：待机、行走、挥锤蓄力／挥击／收招、掷锤蓄力／离手／等回锤／接锤、落雷引导／收招、受击亮色、败退。招式先做单方向代表小样，确认可读性后补四向。
- 母图候选画布 1024×1024，身体居中偏下并留武器运动余量；最终显示高度按现有孩子实际画面测量后定，不能将概念图比例直接拷入运行时。身体与锤交付透明 PNG，记录统一根点、握点、缩放及逐帧时长。动画路线和费用另依项目指南确定，本轮未生成视频。

## 3. 玩家基线与数值初值

当前规则来源：[training_room.gd](../../godot/scripts/combat/training_room.gd)、[蓝量与精力](../product/首关_蓝量与精力规划_v0.1.md)。移动 220，闪避 600×0.20 秒＝120 距离，前 0.12 秒无敌；普通箭 15／0.35 秒，Q40／4 秒耗12蓝，E15×3／8秒耗28蓝。生命100，受击保护0.60秒。距离为二维世界单位，时间为有效游戏秒。

| Boss 参数 | 起测值 | 目的及边界 |
| --- | ---: | --- |
| 最大生命 | 1200 | 按普通箭理想 DPS42.86 估算，连续命中28秒；不视为平衡结论 |
| 追近移速 | 100 | 低于玩家220；用远程招应对远处玩家 |
| 脚点碰撞／受击半径 | 32／40 | 碰撞与受击分别配置；不按巨型立绘包围盒判定 |
| 普通攻击击退抵抗 | 100% | 不位移，不因普通箭反复取消招式；保留命中光、姿态及真实伤害数字 |
| 掷锤破绽承伤 | ×1.25 | 仅锤离手窗口生效，不另增破防条 |
| 破绽结算 | 每次命中伤害×1.25，四舍五入 | 普通箭19、Q50、E每段19；最终扣血不超过剩余生命 |
| 控制合同 | 硬控≤2秒，结束后免疫5秒 | 沿用确认规则；持续冻结改减速，具体减速待效果规格，不在本轮新增控制技能 |
| 接触伤害 | 无 | 身体接触只阻挡，伤害必须对应招式 |
| 生命阶段 | 一个 | 无血量加速、二阶段、召怪或随机狂暴 |

只用现有固定伤害，不引入物攻、法强、防御、暴击和成长公式。破绽倍率在规则伤害入口算一次，展示与扣血同源；E逐段按该段发生时是否仍在破绽判断。普攻击退免疫不等于所有控制免疫。

## 4. 三招合同

### A. 断步横锤：检查近距离贪刀

距离≤160时可选。0.80秒蓄力，起手即锁定方向；地面显示110°扇形、半径180。挥击有效0.12秒，伤害20，同次挥击最多命中玩家一次；之后收招1.00秒。蓄力及挥击均不追踪转向、不滑步贴人。玩家侧移离开扇形或退至范围外；闪避是兜底。动作首次出现用完整时长，不能突然取消预警换招。

### B. 离手雷锤：引导横移并奖励反击

距离>160时可选。1.00秒蓄力，前0.65秒跟随瞄准，最后0.35秒锁定方向与直线路径，地面预告宽96。锤中心最远飞600，速度500，随后沿原路径回返，速度650；单程接触边界即折返。飞行半径36，玩家受击采用自身实际半径，与预告宽度一并校准。

去程伤害20，回程伤害15；每程最多命中一次，仍受玩家0.60秒保护约束。回锤不追踪玩家，也不根据玩家后来的位置改线；索尔自离手起站定且×1.25承伤，到回锤接回为止，最远完整窗口约600/500＋600/650＝2.12秒。窗口随离手立即开启、随接锤立即关闭，锤只在规则层有一个实例。接锤后额外收招0.80秒，期间恢复正常承伤。

反制为横向离开预告路线，在安全侧翼射箭，勿沿锤路追击。不能要求连续两次闪避才能躲开。场地预留完整600飞距，避免贴边过早折返造成不可反应；若实际碰撞使窗口不足1.20秒，该出生／站位组合列为失败样例并先调场地。

### C. 三点落雷：打断站桩，给精力恢复时间

掷锤完成后使用。索尔举锤0.60秒后，在t=0.60、1.30、2.00秒各记录一次玩家当时位置；每处落点预告1.00秒后落雷，圆半径80，伤害15、判定0.10秒，不留持续电场。落点记录后固定，不追踪。最后一次落雷在t=3.00秒发生，收招1.00秒后结束，全招4.00秒。

玩家以220移速直走1秒可离开半径80圆，通常无需消耗闪避。三次雷独立去重并遵守玩家受击保护，停留不叠每帧伤害。三圆可能重叠但不封闭全场，不与其他招同时进行；该招内索尔不追近、不附带近战。

## 5. 编排、状态与场地

首次开战有1.20秒可观察准备。之后固定决策：距离≤160则A一次，>160则直接B；A收招结束后追近或原地准备最多1.50秒，再强制B；B之后固定C；C完成后回到距离决策。每循环A最多一次，保证远程攻击出现，不以全随机决定教学顺序。距离取每次决策时的脚点距离。

规则状态：准备 → 决策／追近 → 招式前摇 → 生效／飞行 → 收招 → 下一招；死亡在任意状态优先进入败退。每个状态有确定剩余时间，大时间步也必须跨过并执行到期事件，不允许跳过命中或多派发。

独立测试房候选1440×1040，四周96安全边距，可用区域1248×848，先无柱子和装饰障碍。玩家与Boss初始距离约420；中心位置为掷锤留足600通路。镜头验证要保证远端预警、锤与玩家同时可见，不能用房间世界尺寸假定屏幕全可见。锤不能从视野外无预警伤人。身体不可把玩家挤入墙角；闪避沿用可穿敌人、不可穿墙规则。

灰盒实现细化：为满足前述至少1.20秒离手窗口，Boss出生和追近限定在x472—968、y472—568的中央区域；飞锤中心扣除自身半径后，任何方向仍有至少340单位飞距。玩家活动区保持原尺寸。场地扩大后可重算，不改变飞行速度来掩盖短路径。

暂停／失焦：冻结规则时钟、预告、弹道、伤害与资源恢复；不借中断重选落雷位置。窗口变化按现有输入适配清意图，不擅自暂停所有规则。重试清锤、雷、命中去重及Boss状态。Boss死亡立即停止全部攻击、清残余威胁，胜利只发生一次。原型不增加一炷香系统；正式接入后应进入停时战后结算，而非将死亡直接等同本局完成。

## 6. 续航与验证预算

正式跨房不补满；蓝量不会自然恢复，原型不加入小怪回蓝、命中回蓝或药剂。独立房以固定夹具分别测100、44、0蓝；生命100为基础，再测40生命低容错；精力分别测100和0的恢复场景，原有恢复等待也要可输入。

1200血零破绽需80支普通箭，理想约28秒；全部破绽命中需64支19伤箭，实际窗口占比不可能覆盖全部。目标有效战斗时间50—80秒对应约35%—56%的理想普攻输出，作为观察区间而非强制倒计时。44蓝可支付Q×3（36蓝）或Q＋E（40蓝），因此E不作为单体战必需解法。生命100可承受4次20伤，第5次失败；低血到达不是可保证无失误通关的平衡承诺。

精力最多四次连闪，之后需要恢复。若试玩每个循环必须两次以上闪避才可存活，先修预告／范围／编排，不能靠无限精力掩盖问题。落雷可行走规避，B可横移规避，只有站位失误时依赖闪避。

记录：进入资源、击败时间、每招受击次数、普攻/Q/E实际命中、破绽伤害占比、闪避与精力见底次数、看不见的预告。先验证可读和可躲，再调出手频率与伤害，最后按实际命中效率调生命；不同时改多组参数。原型初轮可用每个资源夹具3次人工试玩观察趋势，样本不代表玩家总体胜率。

## 8. 验证清单与交付限制

实现阶段扩展现有 `godot/tests/run_tests.gd`，不新建测试框架。重点锁定：招式锁定时刻、范围边界、每招命中次数、0.60秒保护、破绽开闭同一时刻的事件顺序、E跨窗口逐段结算、最后一击截断、Boss死亡优先于后续攻击、R清理、暂停冻结、失焦输入取消、大时间步等价。破绽边界采用半开区间[离手,接回)，在接回时刻到达的伤害按正常倍率；死亡后不再生成到期事件。

修改Godot代码后运行 `python3 tools/migration/check_godot.py`；可单跑 `godot --headless --path godot --script res://tests/run_tests.gd` 定位。素材接入做干净导入和 `python3 tools/migration/export_godot.py`，分别记录构建、实际运行与体验结果。按项目要求更新实施记录中Task及待验项，不将本设计任务记成迁移验收已完成。

当前只执行后台验证。没有用户安排不启动真实窗口或发系统键鼠；Windows实测暂缓，双平台体验仍待证据。独立原型通过只证明Boss切片，不代表完整神降／战后签署／检查点闭环完成。
