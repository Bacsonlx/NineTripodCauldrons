# MVP-01：汤谷单房间跑动、瞄准与射箭（macOS／Windows）

> **历史阶段说明**：本文件为 2026-10-16 Electron／Phaser 阶段 MVP-01（[GitHub #1](https://github.com/Bacsonlx/NineTripodCauldrons/issues/1)）的冻结规格合同。现役工程已迁移至 Godot 原生 2D（见[架构选型结论](../architecture/九鼎_架构选型结论.md)、[Godot 迁移 Spec](九鼎_Godot迁移_Spec.md)及[玩法与运行规则](../product/十日_玩法与运行规则.md)），本规格及其历史验收记录独立保留，不代表当前 Godot 首关范围。

## Problem Statement

《九鼎》（副IP《十日》）已确定固定等距2.5D、民俗皮影与木刻轮廓、像素质感，以及移动与瞄准分离的弓箭操作，但目前只有Electron／Phaser初始化入口。现有概念图不能证明人物动起来是否自然、空间关系是否清晰、箭是否正确命中，或两个桌面平台是否能稳定运行。

用户需要先用最小可操作场景验证动作、空间和动态画风，避免在Boss、剧情或完整资产制作前扩大成本。本规格由已收束的两轮访谈Q1—Q9合成；当前没有对应玩法实现、美术交付或性能实测结果。

## Solution

提供一个汤谷风格的固定单屏房间：同一个孩子身体使用后羿弓，支持WASD跑动、鼠标独立瞄准、短按射箭与按住连射，绕开三个石柱并射击两个静态训练靶。靶命中有闪色、局部火花与计数；玩家可暂停、恢复和一键重置。

分两阶段验收：

1. **阶段A：占位功能。** 用占位素材跑通操作、碰撞、反馈与状态边界，并在两个目标平台运行。
2. **阶段B：代表画风。** 先做少量人物动作样例，再确定分层、方向数与帧数，替换人物、弓箭、地面、石柱，并复验功能、动态画风与性能。

Apple Silicon Mac与Windows x64各至少一台实机，分别运行可解压的ZIP产物；两阶段和两平台都通过才算完成。此规格中的“房间”是练习场景，不模拟一整次神降，也不验证完整肉鸽战斗乐趣。

## User Stories

1. 作为玩家，我希望启动后直接进入一个小房间，以便立即体验操作。
2. 作为玩家，我希望持续使用同一个孩子身体，以便保持已经确定的身份与视觉连续性。
3. 作为玩家，我希望用WASD按屏幕方向跑动，以便不必理解等距网格坐标。
4. 作为玩家，我希望松键停止、相反输入抵消，以便控制人物位置。
5. 作为玩家，我希望斜向与直向等速，以便移动方向不影响跑速。
6. 作为玩家，我希望鼠标独立控制瞄准，以便边移动边向另一方向射击。
7. 作为玩家，我希望原地绕身瞄准时人物与弓的指向稳定，以便清楚判断射击方向。
8. 作为玩家，我希望准星在窗口缩放或留边后仍准确，以便所指与箭路一致。
9. 作为玩家，我希望可攻击时短按射一箭，以便精确测试单次攻击。
10. 作为玩家，我希望按住左键按固定间隔连射，以便持续跑射。
11. 作为玩家，我希望普通松手让已经开始拉弦的一箭完成，并停止后续连射，以便短按有明确结果。
12. 作为玩家，我希望攻击间隔内的短按不排队，以便不会在停止点击后突然补发多箭。
13. 作为玩家，我希望射箭有拉弦、放箭与收势反馈，以便看清攻击周期。
14. 作为玩家，我希望射箭不中断跑动，以便验证移动与瞄准分离的操作。
15. 作为玩家，我希望箭从弓口沿所瞄方向直线飞行，以便弹道可预测。
16. 作为玩家，我希望箭在第一个有效接触处结束，以便障碍确实能挡住靶子。
17. 作为玩家，我希望贴柱射击不会在柱后生成箭，以便近障碍的射击结果可信。
18. 作为玩家，我希望较快的箭不会跳过薄靶或柱边，以便命中结果稳定。
19. 作为玩家，我希望每支箭只增加一次命中计数，以便反馈不会重复。
20. 作为玩家，我希望靶受击时闪色并出现局部火花，以便无需伤害数字也能辨认命中。
21. 作为玩家，我希望空射或击中石柱不增加靶命中数，以便区分射击结果。
22. 作为玩家，我希望靶不移动、不攻击、不被摧毁，以便反复练习同一操作。
23. 作为玩家，我希望人物不能穿过房间边界或柱基，但能沿阻挡面移动，以便绕行自然。
24. 作为玩家，我希望可见柱身阻挡箭、可见靶面接收箭，以便看到的接触与实际结果一致。
25. 作为玩家，我希望人物绕柱时前后关系与影子正确，以便理解2.5D空间。
26. 作为玩家，我希望一靶可直射、另一靶需要绕柱，以便在同一房间检查瞄准与阻挡。
27. 作为玩家，我希望箭射空后及时消失，以便长时间练习不堆积对象。
28. 作为玩家，我希望Esc能暂停与恢复，以便中断操作时场景不继续推进。
29. 作为玩家，我希望切出窗口自动暂停，返回后手动恢复且重新输入，以便没有粘键或自行续射。
30. 作为玩家，我希望鼠标离开有效画面或进入黑边时取消未放出的箭并停止连射，以便画外输入不造成意外攻击。
31. 作为玩家，我希望鼠标重新进入画面后需要重新按下才射击，以便不会沿用旧的按住状态。
32. 作为玩家，我希望按R清除练习状态并归位，以便重复验证同一场景。
33. 作为玩家，我希望重开应用回到初始房间，以便无需处理练习存档。
34. 作为玩家，我希望操作说明和命中计数简短可读，以便界面不遮住人物与弹道。
35. 作为玩家，我希望必要素材加载失败时看到明确提示，以便不会把空白或失效场景当成可操作状态。
36. 作为美术制作者，我希望先验证少量分层与反向跑射样例，再决定完整方向数和帧数，以便减少返工。
37. 作为美术制作者，我希望掌握最小资产集合、连接点与交付约定，以便不用先制作完整游戏素材。
38. 作为项目负责人，我希望先验收占位功能再验收动态画风，以便分别识别操作与素材问题。
39. 作为Mac使用者，我希望能解压并运行Apple Silicon版本，以便验证实际桌面产物。
40. 作为Windows使用者，我希望能解压并运行x64版本，以便这一步就覆盖Windows。
41. 作为验收者，我希望两个平台分别满足相同的帧率和稳定性门槛，以便不能用一端结果代替另一端。
42. 作为后续实施者，我希望规格内包含全部行为、资产与验收要求，以便不依赖聊天历史继续工作。

## Implementation Decisions

### 已有基础与职责

- 沿用TypeScript、Phaser 3.90.0 WebGL、Electron 44.8.0、Forge／Webpack与现有隔离桌面能力；不在此规格中升级或替换技术栈。
- 目前游戏场景只显示标题和版本；没有移动、瞄准、攻击、碰撞、暂停或战斗测试实现。现有设计画布为1280×720，等比适配并居中；已有macOS与Windows ZIP maker配置。
- 在现有游戏场景入口承载房间体验；输入、移动、瞄准、攻击周期、箭、碰撞、动画与反馈留在游戏渲染进程。桌面侧继续负责窗口与生命周期，不逐帧通过IPC传输战斗状态。
- 移动意图、攻击周期和动画播放必须可以区分；动作显示帧不能反复生成箭，射箭不能锁住下身移动。无需为此预先引入复杂实体框架、数据库或新的逐帧进程接口。

### 房间与人物

- 单个固定汤谷庭院；相机不旋转、滚动或追随；地面采用一张低噪声固定底图，人物、柱、靶和必要遮挡物独立，不把它们画死在底图中。
- 固定放置一个玩家、同款石柱三个实例、同款静态靶两个实例。左下偏内安全出生，一靶可直射，另一靶从出生点被中部柱挡住且可绕行射中；第三类位置用于贴边与遮挡测试。实际布局须通过连线和通路检查，不能只按文字示意摆放。
- WASD朝屏幕上、左、下、右移动；组合形成八方向。相反输入抵消，斜向归一，不做慢走、冲刺、体力或惯性。松键停止；完全被阻挡时不持续原地跑步，沿阻挡面仍可滑行。
- 玩家按脚点与柱基判断通行；弓、头发、红巾不扩大通行碰撞范围。靶不阻挡玩家，不做推挤。
- 鼠标控制360°瞄准；方向数只影响美术姿态，不限制真实弹道。初始有效瞄准前朝右；鼠标几乎与参考点重合时保留上次有效方向，方向分界不抖动。
- 绕身瞄准、左右与上下反向跑射先以少量样例验证，再定拆层、方向数和帧数。四向与旧估算44帧均非固定交付承诺；不能靠缩减瞄准角度掩盖拼接失败。

### 攻击与命中

- 可攻击时短按左键开始一次攻击；按住按固定间隔开始后续攻击。普通松手让已经开始拉弦的一箭完成，并停止后续连射。间隔内短按忽略、不排队；持续按住可在下一可攻击时点开始新攻击。
- 攻击经历拉弦、放箭、收势与间隔；每周期只生成一支箭。放箭时取当前有效瞄准，移动和瞄准均可继续，不做蓄力、多重箭或回收。
- 箭从可见释放点沿直线匀速飞行；箭身方向与弹道一致，不追踪、反弹或穿透。准星表示箭要经过的位置，弓口、箭路、可见目标与反馈点一致。
- 箭按可见柱身及靶面定义的简化区域命中，不能共用柱基通行范围或以靶影为靶面；不做真实高度或三维碰撞。
- 按运动轨迹的首次有效接触结算，防止单帧位移较大时跳过薄靶或柱边；贴柱还须防止释放点落到障碍另一侧。靶与柱同时在路线上时先遇柱则不得命中靶。
- 命中靶：箭结束，命中数加一，靶闪色、局部金色火花；每箭最多一次。命中柱或边界：箭结束、弱火花、计数不变。射空至出界或最长存续结束时清理，不永久留箭。
- 靶没有AI、生命、攻击或死亡；命中不算通关。人物与柱按脚点前后排序，影子贴地，必要时低矮柱或局部淡化保证人物可读。

### 输入边界、暂停和重置

- 仅有效游戏画面内的鼠标坐标和点击可用于射击，等比留边及缩放不能改变映射。
- 鼠标进入黑边或离开有效画面时，取消未放出的箭并清除连射；已飞出箭继续，键盘移动仍可用。返回画面后重新按下左键才射击，不沿用画外或离开前的按住。
- Esc暂停／恢复；失焦自动暂停，返回仍保持暂停直至Esc恢复。暂停停止人物、箭、效果和攻击间隔，清空输入，取消未放出攻击，不积压或补发；已飞出箭冻结后继续。恢复后需重新输入，不能自行续跑或续射。
- 运行中R重置，暂停时R不生效，按住R不重复触发。重置归位玩家、恢复靶外观、清计数／箭／效果／输入／未放出攻击、恢复可攻击状态及默认朝向，等待新输入；反复重置不增加对象或事件回调。
- 退出重开回到初始房间，不保存练习进度。加载中不接受操作，必要素材失败显示明确错误，不进入半失效房间。
- UI只保留操作说明与命中计数、暂停短提示；不新增完整菜单或正式战斗HUD。

- 风格以皮影轮廓、木刻材质、赭灰汤谷、金色己方攻击为基准，像素质感为辅；不复制概念图中Boss、太阳主动技或密集装饰。
- 动画离线制作，最终导出透明序列帧／图集与帧描述，不新增骨骼运行时；保留可编辑源文件、裁切偏移、连接点和制作说明。未验证前不锁所有素材统一4K或固定帧数。
- 字体使用可读中文资源，不制作新字库与整套正式UI。引入第三方素材时保留来源与授权，不凭登记条数推算工作量。

## Testing Decisions

### 测试入口与现状

- 主要测试入口沿用已确认的**单房间可操作体验**：从真实游戏输入与场景推进，观察人物、箭、目标、计数、暂停和重置的外部结果。优先复用现有Phaser场景入口，避免为每个内部函数建立测试接口。
- 覆盖责任包括房间与输入、移动／瞄准／攻击协作、首次碰撞与反馈、动画和遮挡、窗口焦点／缩放、资源加载与打包运行。职责划分不要求预先拆成同数量的新模块。
- 自动化检查优先覆盖斜向速度、攻击节流、首次接触、一次计数、暂停与重置等容易出错的外部行为；美术连接、遮挡观感与实机性能用实际画面和记录验证。不得用私有函数调用、模拟返回成功或标题截图替代体验验收。
- 当前没有战斗测试框架或测试脚本可直接复用；已有先例是类型检查、桌面开发启动与macOS初始化打包检查。它们可验证入口与构建，但不能作为本MVP玩法、Windows或性能已通过的证据。

### 功能与美术验收

以下19个用例全部待执行。最终代表素材阶段须复验受影响功能；仅占位阶段通过不能关闭整个规格。

| ID | 场景与操作 | 预期结果 |
| --- | --- | --- |

### 双平台性能与完成条件

| 事项 | 两端相同要求 |
| --- | --- |
| 设备 | Apple Silicon Mac与Windows x64，各至少一台真实设备；记录实际系统、CPU／GPU与内存 |
| 产物 | 分别对应平台的可解压运行ZIP；最终用同一版场景、素材和玩法参数验收 |
| 输出与目标 | 1920×1080输出，以60 FPS为目标；允许1280×720内部画布等比输出 |
| 采样 | 必要素材完成加载并预热后，前台连续跑动射击完整60秒 |
| 平均帧率 | 至少58 FPS |
| 帧间隔 | 至少95%的有效呈现帧间隔≤20毫秒，不能用单段JS执行耗时替代 |

| 非稳定事件 | 加载、暂停、窗口切换单独做功能验收；打断采样后重新稳定并采满60秒，记录原因，不能删除卡顿帧凑门槛 |
