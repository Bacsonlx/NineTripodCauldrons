## 1. 目标与完成定义

### 1.1 要解决的问题

当前第一关已经具备独立房间、基础战斗、药瓶、装备来源、背包摆放和部分祭坛规则，但玩家仍可能把它理解成：

- 先拿到道具，再把道具放进空位；
- 技能来源和神兽只是面板标签；
- 祭坛的空间关系不改变实际战斗；
- Boss 只是更大的血条和已有招式；
- 高难度只能依靠敌人血量与伤害变大；
- 背包、战斗、Boss、残碑和下一局之间没有形成同一条记忆链。

本计划要让玩家在第一关内连续做出四类可感知的决定：

1. **空间决定动作：** 物品摆放的正交关系改变箭、闪避、击退、牵引和火焰的操作方式。
2. **开局决定承诺：** 神兽三选一确定本局底色，后续两次重念让同一个底色完成质变。
3. **构筑决定 Boss 关系：** 十容器的票数、排名、对冲和点燃结果被 Boss 念名、招式和弱点读出来。
4. **规则决定重玩价值：** 惩罚契约改变战场规则和决策压力，而不是只增加生命值。

### 1.2 完成定义

本计划完成后，第一关必须满足以下条件：

- 正式完整征程仍是入口到索尔再到出口的连续一局，包含现有十六房结构、主线与支路、房间往返和当前已确认的 15–20 分钟目标。
- 祭坛 4×4、中央 2×2 主位、外圈环位、曼哈顿正交邻接和 BFS 通电是唯一空间裁决。
- 同一构筑在没有通电时不触发空间共鸣；仅改变位置但没有形成合法网络时不应产生战斗效果。
- 至少四组动作质变在规则层真实改变战斗行为，并由 HUD 或战场反馈说明其已生效。
- 入口可以完成青龙、白虎、朱雀三选一；神兽在本局锁定；两个安全节点各提供一次确定性重念。
- 三种神兽至少各有一条从初念到三念的实际动作路线，不能只替换名称、颜色或百分比。
- 索尔仍遵守项目现行 Boss 与十容器规则；Boss 念名、弱点、断招和残碑铭刻来自实际构筑状态。
- 至少五种惩罚契约改变房间机制、玩家路线或 Boss 招式；契约不以简单的 HP／ATK 倍增作为主要内容。
- 规则测试、Godot 导入检查和完整场景后台检查通过；视觉、交互、性能和 Windows 实机状态分别记录，不用无头结果代替。

## 4. 系统边界与数据流

本轮必须保持六个层次分离，避免把所有意义塞进一次摆放计算。

```text
背包真实空间
    ├── 祭坛几何层：主位／环位／正交邻接／BFS 通电
    │       └── 动作共鸣：埋雷、牵引、推击、分裂、心流
    ├── 十容器语义层：票数／排名／对冲／作祟／点燃
    │       └── 世界记法：Boss 念名、弱点、招式、残碑铭刻
    ├── 神兽祝词层：入口选择／初念／再念／三念
    │       └── 本局承诺：风、斗、火三条动作路线
    ├── 惩罚契约层：玩家选择的机制变异
    │       └── 房间环境、弹道、Boss 招式和重念限制
    └── 呈现层：HUD／战场反馈／剪影／残碑
```

数据流要求：

1. `AlphaState` 计算背包、祭坛、十容器和神兽的公开快照。
2. `TrainingRoom` 只依据公开快照和房间契约裁决战斗，不从 HUD 或动画反推规则。
3. `room_journey.gd` 管理一局的房间进度、重念节点、契约状态和战后结算点。
4. `presentation/` 只消费快照和事件，负责反馈，不新增伤害、击退或 Boss 弱点规则。
5. 局后铭刻只在战后检查点提交；阵亡、重开和快速测试不伪造跨局存档。

## 5. 详细施工顺序

### 阶段 0：基线冻结与失败反馈回路

**目的：** 先把当前集成分支恢复到可重复验证状态，再继续扩大玩法。

**工作内容：**

- 运行完整 Godot 检查和既有规则测试。
- 修复首个解析、类型、规则或退出码问题。
- 为商业深度建立统一公开快照字段，禁止测试直接读取私有变量。
- 建立本轮测试文件 `godot/tests/commercial_depth_checks.gd`，先写反例：
  - 未通电的相同物品不触发共鸣；
  - 物品只换位置但没有能源源头不触发；
  - 快速测试仍保持旧奖励合同；
  - 正式首关才使用商业深度奖励循环。
- 更新实施记录，区分构建／逻辑／运行／交互／视觉／性能六类证据。

**通过门槛：**

- `python3 tools/migration/check_godot.py` 通过。
- `godot --headless --path godot --script res://tests/run_tests.gd` 通过。
- `godot --headless --path godot --script res://tests/backpack_deep_checks.gd` 通过。
- 新测试能够证明“未接通就不生效”，而不是只证明正例可用。

### 阶段 1：祭坛空间构筑与动作质变

**目的：** 让玩家第一次摆放祭坛时就能感到“位置产生操作意义”。

**规则合同：**

- 主位为中央 2×2，器是能源源头。
- 环位为外圈 12 格，符与契通过正交边接入网络。
- 对角线不算邻接。
- 只有接入能源的物品才进入有效共鸣。
- 共鸣只改变操作和空间关系，不能把设计退化成伤害乘区。

**首批正式共鸣：**

| 共鸣 | 真实操作改变 | 主要验证 |
| --- | --- | --- |
| 羊角 + 虎牙 | 普通箭／穿透箭命中或落地埋下 3 秒地雷；玩家闪避接触或敌人踩踏引爆范围冲击 | 埋雷寿命、触发位置、范围伤害、清理和反馈 |
| 鼠毫 + 鼠毫 | 命中后的箭产生牵引回收反馈，并让玩家向命中点短距离位移 | 命中、落地、墙体、位移边界和连续触发 |
| 虎牙 + 快马主位 | 暴击转为强制击退与短硬直，不再额外乘伤害 | 暴击替换关系、Boss 保护、击退碰撞 |
| 燧火 + 燧火 | 燃烧目标死亡时把火焰传向附近目标 | 派生伤害不递归触发命中／暴击，死亡只结算一次 |
| 素食 + 两个邻接符 | 脱战后形成短暂心流，改变蓄力或弹道行为 | 营地、暂停、阅读和安全走动不错误推进 |

**实现落点：**

- `godot/scripts/alpha/altar_geometry.gd`
- `godot/scripts/alpha/alpha_state.gd`
- `godot/scripts/alpha/equipment_skills.gd`
- `godot/scripts/combat/training_room.gd`
- `godot/scripts/presentation/combat_overlay.gd`
- `godot/scripts/presentation/combat_effects.gd`

**通过门槛：**

- 每组共鸣都有“通电正例”和“未通电反例”。
- 同一个构筑改变位置后，战斗快照能明确显示生效／失效。
- 地雷、牵引、推击、分裂都能从战斗快照和事件层回放，不能只在画面上闪一下。
- 不改变十容器原有的票数、排名、对冲、点燃和残影规则。

### 阶段 2：神兽三选一与祝词三阶承诺

**目的：** 让玩家在入口就知道本局要练成什么，并且敢围绕它做空间决定。

**入口流程：**

1. 入口营地首次进入时展示青龙、白虎、朱雀三张祝词卡。
2. 玩家选择一只，写入本局 `blessing`，并锁定到本局结束。
3. 出发后不能更换神兽，随机奖励不能覆盖神兽。
4. 快速测试可以使用默认合法状态，但不能伪造完整征程的前序奖励。

**三条动作路线：**

| 神兽 | 初念 | 再念 | 三念 |
| --- | --- | --- | --- |
| 青龙 | 引风位移留下短风道，风道提供移动与穿透窗口 | 风道形成短时实体风墙，可挡住纸矢或改变走位 | 箭命中风道时引爆多重风刃，风道消耗并产生新的空间节奏 |
| 白虎 | 暴击或蓄力命中给目标留下“裂痕”，下一次直接箭命中裂痕产生撕裂硬直 | 闪避穿过裂痕目标时触发近身冲击，改变闪避的进攻用途 | 裂痕可沿同一方向传递，玩家需要管理目标排列而不是只追求单体伤害 |
| 朱雀 | 命中燃烧目标时在落点留下短时余烬，改变安全路线 | 闪避穿过余烬会把余烬点燃成横向火线，形成可控区域 | 箭雨落点与余烬相连时提前引爆火羽，改变箭雨的布置与撤离时机 |

每一阶都必须通过“去掉数值后仍然是不同操作”的审查。若描述只剩“伤害增加、持续时间增加、范围增加”，则不能进入正式实现。

**安全节点：**

- 第一个已确认的安全整理点提供第一次重念。
- 雷庭前径或第二个已确认安全节点提供第二次重念。
- 每局最多两次，重复进入节点不能重复升级。
- 重念期间暂停战斗计时，离开后恢复；不免费回复资源。

**实现落点：**

- `alpha_state.gd` 的祝词状态与公开快照
- `room_journey.gd` 的节点解锁和一次性消费
- `camp_panel.gd` 的三选一与重念 UI
- `combat_hud.gd` 的当前神兽、阶位和下一阶提示
- `training_room.gd` 的三种祝词动作裁决

**通过门槛：**

- 三种神兽均能完成入口选择、锁定、重念和本局结算。
- 祝词状态随房间切换保留，R 重开清空。
- 旧青龙行为继续可用，白虎和朱雀有实际战斗差异。
- 测试能证明第三次重念、重复消费和离开节点后的非法操作均被拒绝。

### 阶段 3：奖励、整理与构筑反馈闭环

**目的：** 让奖励不是随机填格，而是推动玩家继续调整构筑。

**规则合同：**

- 正式首关每局构筑符奖励上限仍按已确认的 7 枚主线、含支路最多 8 枚控制。
- 奖励循环优先保证构筑有机会形成至少一组空间共鸣。
- 奖励不无限发放，不因为往返房间重复清场。
- 快速测试和旧规则夹具保留原有合同。
- 营地整理、战斗快选、点燃、物品落地和残影继续遵守现行规则。

**需要补齐的反馈：**

- 拾取时提示“可能形成的共鸣”与“当前已通电的共鸣”分开显示。
- 背包中显示通电边、能源源头、失效原因和下一步可摆位置。
- 营地显示当前祝词路线、可重念次数、契约负担和 Boss 前准备状态。
- 战斗中只显示会影响当前操作的少量提示，避免把背包面板复制到 HUD。

**通过门槛：**

- 玩家可以在不打开调试信息的情况下判断某件物品为什么生效或失效。
- 玩家在一局中至少有一次“保留当前构筑”和“点燃／换位获得短期收益”的明确取舍。
- 奖励不会让第一关变成无意义的满格收集。

### 阶段 4：十容器语义、Boss 念名与残碑铭刻

**目的：** 把“被谁记住”从文档规则变成 Boss 战和战后记忆。

**硬约束：**

- Boss 仍为索尔，保留现有追近、横扫、落雷、援军和药囊合同。
- 不创建一套独立的 Boss 属性表来替代十容器。
- Boss 的念名、弱点和断招条件必须可追溯到当前十容器的票数、排名、对冲、作祟和点燃结果。

**Boss 交互：**

1. Boss 房进入时，根据当前排名生成 1 个主念名和 1 个弱点提示。
2. 主念名对应当前最高显灵容器；第二名或对冲结果决定 Boss 的辅助招式或保护方式。
3. 特定空间共鸣或祝词动作命中弱点时，进入规则层的短暂断招窗口。
4. Boss 转阶段时重新念名，但不随机重写玩家构筑。
5. HUD 在 Boss 血条下显示当前念名、弱点触发条件和断招冷却。

**战后铭刻：**

- Boss 归零后进入战后检查点，不立即结束整局。
- 铭刻内容至少包括：
  - 当前祭坛拓扑摘要；
  - 当前神兽和祝词阶位；
  - 当前有效显灵、作祟和点燃状态；
  - 本局已完成的主要动作共鸣；
  - 激活的惩罚契约。
- 铭刻是局后记忆摘要，不伪装成当前尚未实现的完整跨局存档。
- 下一局可通过残碑查看上一局的摘要或残影，但不能直接恢复上一局的生命、奖励和临时状态。

**实现落点：**

- `godot/scripts/alpha/altar_votes.gd`
- `godot/scripts/alpha/alpha_state.gd`
- `godot/scripts/combat/boss_room.gd`
- `godot/scripts/journey/room_journey.gd`
- `godot/scripts/presentation/combat_hud.gd`
- `godot/scripts/presentation/boss_view.gd`
- `godot/scripts/presentation/room_journey_scene.gd`

**通过门槛：**

- 改变十容器排名会改变 Boss 念名或弱点说明。
- 断招只在合法触发条件下发生，不能由 HUD 或动画强行触发。
- Boss 战后可以回查本局铭刻，R 重开不会伪造上一局记忆。

### 阶段 5：十容器作祟惩罚契约

**目的：** 让高难模式要求玩家理解构筑、走位和资源，而不是延长打靶时间。

**第一批契约：**

| 契约 | 机制变化 | 对应的玩家决策 |
| --- | --- | --- |
| 地火割裂 | 场地周期性出现可预警的持续地火线 | 重新选择撤离路线、风道和地雷位置 |
| 逆风偏折 | 箭矢受到方向性偏折，命中窗口和走位关系改变 | 近距离射击、预判和白虎／青龙路线取舍 |
| 空位落雷 | 祭坛存在未通电空位时，房间周期性出现落雷预警 | 选择补齐祭坛、承担空位风险或调整主位 |
| 雷庭狂暴 | 索尔在指定阶段变更追近、横扫或落雷编排 | 读取念名与弱点，不能只靠堆伤害 |
| 重念限制 | 本局只有一次重念，或第二次重念需要完成额外房间条件 | 提前决定祝词路线，不把升级当成无条件保险 |

**契约原则：**

- 每个契约必须能从 HUD、场地预警或 Boss 动作中读懂。
- 契约不能暗中改变基础碰撞、操作中断和已确认的资源规则。
- 至少一项契约要和祭坛拓扑直接交互，但不能因为一个空格就无解释地惩罚玩家。
- 契约完成后的奖励优先是残碑印鉴、解锁记录或后续挑战入口，不直接发放无限战斗数值。
- 第一批只做五种，完成后再评估更多契约，不把十容器十种作祟一次性全部实现。

**实现落点：**

- `room_journey.gd`：本局契约状态、选择、房间传递
- `journey_room.gd`：房间机制入口和预警
- `training_room.gd`：地火、逆风和空位落雷的规则裁决
- `boss_room.gd`：Boss 招式变异
- `camp_panel.gd`、`combat_hud.gd`：选择与当前提示
- `alpha_state.gd`：祭坛拓扑与契约查询

**通过门槛：**

- 五种契约都能激活、保存、跨房间传递、重开清除。
- 关闭契约时基线战斗不变化。
- 契约效果有明确预警、快照状态和结算记录。
- 契约不会通过血量膨胀掩盖走位和构筑问题。

### 阶段 6：暖干骨白视觉与三级 HUD

**目的：** 让玩家在乱战中看清自己的动作、敌人的威胁和当前构筑状态。

**视觉合同：**

- 背景主色：`#D8CFC0`。
- 结构暗部：`#2A211C`。
- 朱红重点：`#C8382B`，只用于危险、Boss、点燃和核心反馈。
- 角色、敌人、箭矢和重要投影使用统一硬边和高反差描边。
- 边缘暗角目标约 15%，必须先用原生场景截图确认不会吞掉远处箭矢。
- 箭矢与地面保持可识别的明度差，不能只写成一个没有测量方法的口号。

**HUD 顺序：**

1. 行动倒计时：闪避、技能、蓄力、风道、地雷和断招窗口。
2. 可消耗次数：点燃、契约可用次数、药瓶和当前特殊触发次数。
3. 被动层数：燃烧、裂痕、祝词层、显灵层等折叠显示。

**表现工作：**

- 地雷爆炸的落点、范围、命中和消失反馈。
- 牵引回收的路径光迹、位移起止和碰撞保护反馈。
- 推击和 Boss 断招的受击停顿、方向箭头和硬直表现。
- 神兽三阶的风墙、裂痕、余烬和火羽差异。
- Boss 登场、念名、转阶段和铭刻使用残碑剪影模板。

**通过门槛：**

- HUD 不再固定显示青龙、固定技能来源或旧奖励文案。
- 所有可行动信息在 1080p 画面中能快速定位。
- 后台只能证明节点、颜色值和状态更新；真实可读性必须保留原生窗口前台验收。

### 阶段 7：整关调校、证据和发布候选

**目的：** 证明各系统组合后仍然是一局有节奏的冒险，而不是五个独立 Demo 拼接。

**整关验证路径：**

1. 入口选择神兽。
2. 第一组房间形成至少一组空间共鸣。
3. 第一个安全节点完成第一次重念。
4. 支路或主线获得第二组构筑反馈。
5. 雷庭前径完成第二次重念或契约条件。
6. Boss 念名、弱点和断招发生。
7. 战后结算生成残碑铭刻。
8. 重新开始时局内状态清空，上一局铭刻按约定保留。

**必须记录的结果：**

- 规则输入、时间推进和公开快照。
- 暂停、阅读、整理、失焦、重试、死亡和离开确认。
- 祭坛共鸣的通电与失效边界。
- 三神兽和五契约的组合覆盖。
- Boss 战后的结算边界。
- 原生窗口画面、输入流程、性能和稳定性。

## 6. 依赖关系与执行批次

```text
阶段 0 基线冻结
        │
        └── 阶段 1 祭坛空间与动作质变
                  ├── 阶段 2 神兽祝词三阶
                  │       └── 阶段 4 Boss 念名与残碑
                  └── 阶段 3 奖励与构筑反馈
                                  └── 阶段 4 Boss 念名与残碑
                                          └── 阶段 5 惩罚契约

阶段 1 ── 可并行准备 ── 阶段 6 视觉资产合同与 HUD 框架
阶段 5、阶段 6 ── 阶段 7 整关调校与候选验收
```

执行顺序采用“规则先于表现、单一机制先于组合机制”的原则：

1. 阶段 0 先恢复稳定测试。
2. 阶段 1 证明位置会改变动作。
3. 阶段 2 证明本局承诺会沿同一方向成长。
4. 阶段 3 把奖励和整理变成构筑循环。
5. 阶段 4 把构筑结果传入 Boss 和战后记忆。
6. 阶段 5 增加机制级重玩压力。
7. 阶段 6 同步完善读图、反馈和叙事包装。
8. 阶段 7 只在组合闭环后做整关和平台验收。

## 7. 测试与验收矩阵

### 7.1 规则与回归

新增或扩展 `godot/tests/commercial_depth_checks.gd`，至少覆盖：

- 4×4 坐标、主位、环位、边界和旋转。
- 正交邻接与对角线排除。
- BFS 多跳通电。
- 通电前后的共鸣状态差异。
- 埋雷生成、寿命、敌人踩踏、闪避触发、范围伤害和清理。
- 牵引反馈、位移边界、重复命中和墙体碰撞。
- 暴击推击替换倍率、硬直、Boss 保护。
- 三神兽选择、锁定、重念、上限和重开。
- 五契约激活、跨房传递、预警和重开清除。
- Boss 念名、弱点、断招和战后铭刻。

### 7.2 命令

修改 Godot 代码后执行：

```bash
python3 tools/migration/check_godot.py
HOME=/tmp/godot-home godot --headless --path godot --script res://tests/run_tests.gd
HOME=/tmp/godot-home godot --headless --path godot --script res://tests/backpack_deep_checks.gd
```

涉及前台运行、资源导入或原生包时，再按项目规则执行：

```bash
python3 tools/migration/export_godot.py
```

纯文档变更至少检查：

- 新文档相对链接存在；
- 命令、场景名、脚本名和当前分支状态一致；
- 文档没有把“后台通过”写成“视觉／交互／性能已通过”。

### 7.3 证据分类

| 类别 | 本计划的完成证据 | 不能推出的结论 |
| --- | --- | --- |
| 构建／导入 | Godot 检查、导入日志、导出产物 | 不能推出 Windows 实机可用 |
| 逻辑／回归 | 测试用例、公开快照、事件回放 | 不能推出画面手感成立 |
| 运行／加载 | 到达入口、房间、Boss 和结算状态 | 不能推出真实输入顺畅 |
| 交互／流程 | 原生键鼠下的选择、整理、重念、暂停、重试 | 不能用脚本注入完全替代 |
| 视觉／表现 | 指定分辨率、场景和状态的原生截图／录像 | 不能用源图或编辑器节点图替代 |
| 性能／稳定性 | 指定设备、版本、分辨率、时长和原始采样 | 不能用无头帧率替代前台性能 |

## 8. 试玩判断与砍功能条件

以下是调校假设，不是已经通过的指标。每次试玩应记录实际观察和样本边界。

- 玩家在营地主动打开整理的比例目标高于 70%，平均停留时间目标高于 20 秒；如果玩家只在入口摆一次，之后不再整理，优先修正邻接反馈和奖励，而不是继续扩展物品数量。
- 玩家在 Boss 前能说出自己选择的神兽和至少一组有效共鸣；如果只能看到伤害变大，说明动作质变没有传达出来。
- 玩家至少有一次为了形成共鸣而放弃一个看似更强的单件物品；如果所有决策都变成占格和容量检查，说明空间层还没有产生取舍。
- 玩家能从预警和 HUD 读懂契约效果；如果死亡原因只能靠事后解释，契约必须返工。
- Boss 战总时长不应因为契约变成单纯长时间打靶；若主要变化是血条耗时，先削弱数值，再检查机制是否真正改变走位。
- 三神兽中任何一条路线若只是换颜色或加数值，则暂停扩展更多祝词，先重写动作合同。

## 9. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 几何层和十容器层互相污染 | 玩家无法解释为什么生效，规则难以调试 | 两套状态分开计算，分别在 UI 和测试中呈现 |
| 白虎、朱雀只做成数值皮肤 | 三选一没有承诺价值 | 每阶先写“玩家新增了什么操作”，再写数值 |
| Boss 另起属性系统 | 与现行十容器规则冲突，后续内容无法维护 | 只从票数、排名、对冲、作祟和点燃生成念名与弱点 |
| 契约只增加敌人血量 | 高难枯燥，弓箭节奏被拖慢 | 每个契约必须改变场地、弹道、招式或重念条件 |
| HUD 信息爆炸 | 机制越深，读图越差 | 严格按行动倒计时、可消耗次数、被动层数排序 |
| 视觉暗角吞掉远程弹道 | 玩家把清晰度问题误认为难度 | 先做原生截图和明度抽样，再决定暗角强度 |
| 战后铭刻误变成半成品存档 | 重开、死亡和跨局边界混乱 | 先实现战后检查点和只读摘要，完整存档另立规格 |
| 一次性实现全部 153 件道具 | 内容量扩大但决策质量不升 | 先锁首关可掉落池和五组动作共鸣，逐件准入 |
| 后台测试覆盖了但前台手感失败 | 交付结论虚高 | 六类证据分开报告，视觉、交互、性能保留待验状态 |

## 11. 本轮明确不做

- 不接入多人联机、网络同步和实时服务。
- 不把旧 TypeScript、Electron、Phaser 代码重新作为运行时。
- 不新增一套独立技能书、技能槽或稀有度系统。
- 不在第一关同时铺满 153 件道具和全部十容器终极效果。
- 不用完整跨局存档替代当前的战后检查点和铭刻摘要。
- 不把无头测试、编辑器截图或导出成功写成真实窗口视觉、交互、性能或 Windows 实机通过。
- 不因为外部参照存在某个机制，就自动扩大《十日》的玩法范围；每项新增机制必须能回到上述四类玩家决定和现行术语。

## 12. 交付顺序

最终交付按以下顺序形成可审查结果：

1. 规则基线和反例测试通过。
2. 祭坛空间共鸣进入正式战斗。
3. 神兽三选一和两次重念进入完整征程。
4. 奖励、整理和 HUD 能解释当前构筑。
5. 索尔念名、弱点、断招和战后铭刻形成闭环。
6. 五种惩罚契约可选择、可读、可结算。
7. 暖干骨白视觉、残碑剪影和三级 HUD 完成候选。
8. 整关运行、原生交互、视觉和性能证据分别归档。
9. 依据试玩结果决定哪些机制进入下一关，哪些继续留在候选。

在第 8 步完成前，本计划只能称为“商业深度候选施工完成”，不能称为正式发行版完成。
