# Godot 迁移票据拆分草稿

2026-10-19。来源：[迁移规格 #33](https://github.com/Bacsonlx/NineTripodCauldrons/issues/33)。状态：用户要求继续实施全部 Task 后，已发布为 #34—#51；对应链接见 [发布记录](../../migration/godot-tasks.json)。

本组仅覆盖 M0—M4；每个功能票包含规则、实际呈现与对应外部行为测试。T01 为固定参照的先行任务；当前规则层已有独立测试边界，不新增无关重构票。T06 为用户动态小样确认门，确认后才进入完整技能与全图接入。

## 并行与完成边界

- T01 完成后 T02 可开始；T02 的最小双平台原生启动需有真实证据，完整平台功能与性能由 T16／T17 另验。
- T03 完成后，T04 的近战与 T05 的窗口输入可分别推进；T06 同时依赖它们并等待用户实际试玩确认。
- T06 完成后，T07／T08／T09 三种技能与 T10 完整地图可分别推进；T11 阅读需覆盖这三种技能的冻结／中断，因此依赖四票。
- T12 祭坛与 T13 栅门均复用 T11 的安全互动，可以分别推进；T14 在全部探索行为存在后验收四类布局编辑。
- T15 产出同一版本最终候选包，T16 Mac 与 T17 Windows 分别验收；T18 只在两者证据齐全后切主入口。
- 相互独立表示没有业务先决依赖，不保证无共享代码；实施者需协调共用规则与表现接口。
- 已发布为 #33 的子票据并应用 ready-for-agent 标签，使用 GitHub 原生阻塞关系；任务状态以实际验收证据为准。
- 发布保持父规格正文与状态不变；只建立用户确认的子票据关系，不关闭或改写旧 MVP 票据。
