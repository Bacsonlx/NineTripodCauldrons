## Parent

Part of [Spec #1](https://github.com/Bacsonlx/NineTripodCauldrons/issues/1)。

## What to build

在已经通过阶段A的房间中，将少量代表画风的孩子、持弓与动作样例接入真实输入，实际演示绕身瞄准与反向跑射。用画面与操作决定分层、方向数和帧数，再向后续完整角色替换提供可用依据；不只交付脱离游戏的一张立绘。

沿用父Spec的TypeScript／Phaser WebGL／Electron／Forge基线；此MVP保持固定等距2.5D、单屏二维平面，不新增骨骼运行时或逐帧IPC。阶段A先用占位素材，阶段B才验证代表画风。所有结果须标明实际执行平台，未测试不得记通过。

覆盖父规格用户故事：2, 7, 14, 25, 36, 37, 38。覆盖验收：AC-04、AC-05、AC-18；引用用例有拆分时以本票验收条目明确的部分为准。相关资产：MVP-A01、MVP-A02、MVP-A03。

## Acceptance criteria

- [ ] 样例保持同一个孩子身体：黑发轮廓、浅色短衣、靛青裤、朱红长巾、青铜弓作为现有概念方向；皮影轮廓与有限木刻／像素纹理统一，不做换身体或新角色体系。
- [ ] 样例在实际房间输入下覆盖原地绕身瞄准、左右反向跑射、上下反向跑射；箭仍支持360°瞄准，移动不被攻击锁住。
- [ ] 记录脚点、连接点、持弓握点和释放点；没有明显接缝、腰部扭转、弓手脱节、切帧跳点或弓指左箭飞右。
- [ ] 根据样例结果明确可复用部位、拆层方式、所需方向与动作规格，说明不能复用的情况；不把四向、44帧或所有镜像动作可共用当作既定预算。
- [ ] 如果少量样例不能成立，先调整样例和结构，不用限制瞄准角度或大量预制帧掩盖问题；本票以样例验证结论为完成条件。
- [ ] 保留可编辑源、透明序列／图集和元数据及动作演示；运行端不接新骨骼运行时。对应AC-04、AC-05与AC-18角色样例部分。
- [ ] 样例接入后保留已有占位功能，替换受影响部分做回归；未宣称完整角色动作或最终MVP完成。
