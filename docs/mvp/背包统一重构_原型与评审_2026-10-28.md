# 背包统一重构：原型与评审

2026-10-28。用户经 Q1—Q10 访谈全部选择建议方案，并要求开始实现。本轮先交付可评审原型；具体原型获用户确认后再修改 Godot。以下是本轮设计合同，表示后续目标，不表示当前游戏已实现。

## 问题、范围与状态

当前局内面板可见性绑定营地状态，开局默认营地，导致进入关卡即显示整页整理面板。首页则是静态样本与试装标记，没有传入本次征程。B 现用于点燃，I 用于尝试进入营地。原型目标为统一真实背包、主动入口与整理权限。

- Task 1，访谈与源码核查：已完成，Q1—Q10 全部获用户确认。
- Task 2，HTML 交互原型：已制作，[页面](../../output/ui-backpack-prototype-20261028/v1/index.html)、[来源及操作说明](../../output/ui-backpack-prototype-20261028/v1/README.md)。检查结果见下方证据。
- Task 3，原型评审：已通过，用户确认按原型交互推进。
- Task 4，Godot 开发与回归：已完成本轮正式路径接入；macOS 后台与 release 检查另列，Windows 由用户验收。

## 已确认决定

| 问题 | 用户接受的方向 |
| --- | --- |
| Q1 统一概念 | 一个背包入口和页面；内部保留装备、祭坛、普通收纳的功能区别，不保留独立仓库系统。装备与祭坛继续真实邻接。 |
| Q2 首页连续性 | 首页整理直接形成正常出发的初始背包，局内延续本次物品与摆法；不扩展跨局保存。 |
| Q3 操作边界 | 战斗及普通探索仅紧凑查看，不因打开背包暂停，不允许挪位、旋转或换装；安全营地开放完整整理并停时。 |
| Q4 初始物品 | 沿用既有默认装备与领取规则；首页仅展示本次真实持有的物品，不把未实现展示样本或即拾即恢复的药瓶当作可携带实物。 |
| Q5 关闭语义 | B、Esc、关闭按钮结束整理并按既有规则提交最终合法构筑；取消尚未落定的拟放置，返回可操作游戏，不再单设确认构筑出发。 |
| Q6 整理方式 | 点击选中、占格预览、点击合法位置放置；有旋转及取消。非法放置保持原位；拖拽不作为本轮必做。 |
| Q7 信息层级 | 物品空间为主体，选中后在详情区解释作用、状态与可用操作；首页和营地使用同一组织方式，战斗保留同一物品与状态表达。 |
| Q8 容量 | 当前装备30格、祭坛16格、收纳4格，共50格；只画有效区域，原经脉不转作收纳。本轮不实现腰带扩容，不顺带增加容量。 |
| Q9 输入 | B 专用于背包；点燃改 X 并维持不打开背包的战斗操作；移除 I 的独立营地入口，场景营地互动打开同一背包。 |
| Q10 重试 | 正常出发形成初始背包快照，R／失败重试恢复该快照；新征程重新从默认物品准备，不带回局内战利品。快速测试沿用指定条件。 |

游戏默认关闭背包的入口包括正常开局、重试、切房与到达营地。处于安全点不等于已经开始整理；不允许通过仅隐藏面板使游戏继续冻结。关闭可取消拟放置，但不能撤销已确认的嵌符或丢弃操作。嵌符本身不可拆，须在实际执行时说明。

## 与既有规则的关系

- [ADR-0011](../adr/0011-six-system-combat-space-and-progression.md) 的战斗主导、精细整理限营地、真实空间邻接及一键点燃继续成立。
- [技能来源合同](../product/技能来源规则_装备与羁绊.md) 的装备及羁绊自动授予继续成立；没有新增技能书、经脉、启用槽或其他奖励。
- 50格为代码当前30＋16＋4及经脉取消后的起步空间，不是曾显示的80个位置。腰带扩容为既有后续规则，本轮不实现。
- 游戏开发时更新当前有效规则、术语、界面、提示与输入测试；历史记录保留当时含义。技术语境中的代码仓库不属于物品术语清理范围。
- 首页当前展示清单含未实现装备、材料及非持有型药瓶，不能直接当作物品实例来源；需与局内真实定义统一。
- 当前 `depart` 包含最终装备提交、生命上限结算和残影合法性／锁位，开发时需保留完整规则路径，不能只隐藏面板或设置 `camp=false`。

## 原型内容与评审路径

1. 游戏入口：背包默认关闭；点击右下角入口或按 B 打开，再按 B／Esc 收起。
2. 首页准备：选择素食，把它从收纳移到祭坛的高亮邻接格；查看仅携带变为祭坛生效、收纳释放、木票加权。点击踏入汤谷后 B 打开查看相同摆法。
3. 营地整理：选择物品，在格子上预览合法／非法位置；旋转和取消。选择羊角可确认嵌符，收起时预览转为最终生命上限，当前生命不增加。
4. 战斗查看：右侧紧凑布局，背景不遮暗；选物看详情，没有整理操作。X 与 B 分离。
5. 满包反馈：演示既有快马掉落，默认收纳已满，物品仍留地。此标签为评审样例，不新增开局发放。

场景标签为浏览器评审工具，不进入正式游戏。切到满包样例会重置原型样例物品；其他场景共享当前浏览器内存。刷新页面重新开始。原型不实现战斗推进、容器效果、完整掉落领取、暂停／阅读、正式房间切换和存档，因此相关计时及权限文字是设计意图，不是游戏运行证据。

评审重点：入口是否易发现；装备／祭坛／收纳是否易辨；物品生效条件是否清楚；战斗查看是否妨碍主要视野；点击放置是否可理解；页面大小和字号是否可接受。用户尚未认可具体画面。

## Godot 深度实现与验证（外部参照：赛菲莉娅×星界战士×暖雪）

在原型评审通过后，结合外部参照建议《十日 · 外部参照建议 v0.1》（`docs/story/十日_外部参照建议_v0.1.html`）正式推进 Godot 原生代码深度落地，实现“更深入的版本，而不是更大的版本”。

### 1. 赛菲莉娅（背包）：空间分层与几何邻接（把强化推迟到摆好）
- **空间结构分层**：
  - 背包固定 50 格空间：装备 6×5（30格）、祭坛 4×4（16格）、收纳 4×1（4格）。
  - 祭坛 4×4（x: 6..9, y: 0..3）实行明确的几何分层：
    - **主位（中央 2×2）**：位于 (7,1), (8,1), (7,2), (8,2)，放置“器”，作为整座祭坛的阵眼与电源核心。
    - **环位（外圈 12 格）**：放置“符”与“契”，只有与相邻的主位或相邻符物理相邻时才通电生效。
- **几何邻接算法与通电传导（`altar_geometry.gd`）**：
  - 严格计算四向曼哈顿正交相邻（|x1-x2| + |y1-y2| == 1）。
  - 主位器作为通电源，点亮相邻环位符/契；相邻符之间互通形成共鸣网络；未相邻者保持朴素未通电状态。
  - 匹配并输出 8 条手感动作改造词条：
    - 羊角 + 虎牙：【埋雷箭矢】命中的箭插地成雷，闪避碰撞引发范围冲击（伤害变位移埋雷）；
    - 虎牙 + 快马（主位）：【推击强控】暴击不造成纯伤害加成，改为将敌人强力击退 120（数字变位移控制）；
    - 鼠毫 + 鼠毫：【拾取牵引】射出的箭自动飞回，回收动作转为瞬时位移；
    - 燧火 + 燧火：【燃烧分裂】燃烧目标死亡火苗跳向 240 内新目标；
    - 青龙 + 祭坛生肖符：【生肖共鸣】引风风道宽度翻倍且残留时间增加。
- **视觉通电呈现（`item_grid_art.gd`）**：
  - 在网格底层绘制中央 2×2 主位深焦褐底板与骨白微边框；
  - 在通电物品间实时绘制青碧（`#98c8ae`）与赤金（`#e6c27a`）能量连线与节点微光；
  - 通电物品轮廓赋予微光描边，直观呈现“这条边通了电”。

### 2. 星界战士（赐福）：保证演化与神兽三念
- **青龙引风祝词演化机制**：
  - 保证演化：“开局看中的东西，局末一定能长成它的完成形态”。
  - 引入神兽祝词演化阶位（`blessing_tier`: 1~3）：
    - **初念 · 风道疾驰**：冲刺 120 留 3 秒风道，时限内可 0 蓝追加一次；
    - **再念 · 踏风绝尘**：风道可立，踏入风道免疫地面灼烧与陷阱伤害，移速 +30%（已在 `training_room.gd` 中真实生效）；
    - **三念 · 疾风震爆**：普通箭／穿透箭穿过风道时引爆风道，对周围敌人造成一次范围风刃冲击，风道随即消失。
  - **演化节奏**：每局限定 2 次重念演化机会，必须在安全营地（祭火营地 / 雷庭前径）由玩家主动祈愿重念。

### 3. 暖雪（美术）：克制色板与 HUD 分级
- **色板统一落地**：
  - 骨白底 `#D8CFC0` + 焦褐暗部 `#2A211C` + 单点高饱和赤日红 `#C8382B`（<5% 重点操作与状态）；
  - 神兽青碧 `#98C8AE`、祭坛赤金 `#C5A363` / `#E6C27A`。
- **右下角固定入口与 HUD 分级（`combat_hud.gd`）**：
  - 右下角常驻背包入口按钮：未打开时为骨白色【背包 · B】，打开时为赤日红【收起 · B】；
  - 信息分级：顶层可行动（倒计时）> 中层可消耗（次数）> 底层纯状态（数值条）；
  - 彻底移除游戏中所有玩家可见的“仓库”概念，统一规范为“背包”与“收纳区”。
