# 当前开发采用 Godot，双平台交付验收独立跟踪

2026-10-20 更新：用户确认技术方案已迁移到 Godot，并要求同步项目规则和相关文档。当前开发、运行与内容编辑入口统一为 `godot/`，命令见 [Godot README](../../godot/README.md)；Electron／Phaser降为旧版参照，根npm命令仍运行该参照。本轮将开发与文档入口切换为Godot，取代此前等待双平台验收后才更新开发说明的安排；双平台功能、前台性能、稳定性及最终用户确认继续作为交付验收条件，不由文档切换推定通过。原始决策与范围如下。

2026-10-19，用户在迁移方案访谈 Q1 明确决定切换 Godot，以支持二维手绘／精灵、固定俯视或等距表现的 PC／Steam 游戏；接受跨语言移植成本，后续按 Godot 编辑器承载内容调整与验收、AI 负责脚本和批量配置的方式开发。Q2 确认保持已确认的玩法规则、数值、碰撞和操作中断行为，以现有素材与构图作参照，表现改进须经用户确认，已知缺陷单列。

Q4—Q6 进一步确认：首个交付覆盖当前汤谷完整迁移与双平台验收，游戏脚本统一使用带类型的 GDScript，Node.js 可保留用于制作工具；随机房间、Boss、成长、正式存档与 Steam 完整功能按后续商业闭环推进，Steam 早期仅核实接入与兼容风险。

Q7—Q9 确认：迁移按登记的 Windows x64 与 Apple Silicon Mac 实机验收，1080p 连续跑射 60 秒平均 ≥58 FPS、至少 95% 帧间隔 ≤20ms，另做 5 分钟稳定性检查；商业版最低配置后续验证。首个交付完整支持键鼠，手柄留到后续商业闭环；先交付可试玩的动态小样并经用户确认画面和手感，再铺完整汤谷，小样直接复用于正式迁移。

当前主工程已采用Godot，完整汤谷候选已接入并完成后台规则与构建验证；双平台原生验收状态见[候选验收记录](../migration/Godot候选_验收记录.md)。质量或兼容问题在Godot工程修复，不自动恢复为继续采用Phaser的决策。ADR-0006及ADR-0002的Electron容器部分由本决策替代；二维平面、离线图集与跟随镜头决定继续有效。引擎和模板以 `godot/engine-lock.json` 为准，Compatibility的Windows实机兼容仍待验；范围依据见[迁移方案](../九鼎_Godot架构评估与迁移落地方案_2026-10-19.md)。
