# 九鼎：游戏开发 Skills 接入评估

日期：2026-10-20。对象：[gamedev-skills/awesome-gamedev-agent-skills](https://github.com/gamedev-skills/awesome-gamedev-agent-skills/tree/0a70cfc64672d512c5b5b6006b5dcb5cf90dbdbd)，固定提交 `0a70cfc64672d512c5b5b6006b5dcb5cf90dbdbd`。本次完成选择性安装；不是游戏功能交付或效果认证。

## 结论与项目依据

从上游 74 项专业技能选择 **12 项**项目级引入：9 项 Godot 技能和 3 项通用实践。完整名单及触发条件见 [使用指南](../游戏开发Skills使用指南.md)。其余 62 项和额外的通用 router 不安装；不引入插件服务、Node 运行依赖或新图像工具。

当前基线来自 [AGENTS.md](../../AGENTS.md)、[架构结论](../九鼎_架构选型结论.md)、[ADR-0010](../adr/0010-godot-migration-direction.md)、[Godot README](../../godot/README.md) 和 [Sprite Forge 指南](../art/Agent_Sprite_Forge使用指南.md)：Godot 原生 2D、带类型 GDScript、锁定 4.7.2、Compatibility、离线分层精灵、编辑器正式地图；旧 Phaser 只供参照。当前仅后台验证，Windows 实测暂缓。

[昨日初评](九鼎_社区游戏Skills评估_2026-10-19.md) 是未安装时的建议；其中“当前仍运行 Electron／Phaser”是当时状态，本次不沿用为当前基线。今天从基础语言、场景和测试扩展到已有汤谷的呈现、编辑与构建任务；安装这些参考不代表批准新增玩法。

## 筛选结果

以下分类覆盖目录中的 74 项；“暂缓”表示任务或复核条件未满足，不表示质量不合格。非 Godot 引擎按目录及项目范围排除，未逐项验证其 API。

| 分类／数量 | 技能 | 判断 |
| --- | --- | --- |
| 引入：基础与验证，4 | `godot-gdscript`、`godot-nodes-scenes`、`godot-resources`、`godot-gdscript-headless-testing` | 类型、场景、可编辑数据、测试，与当前原生工程直接对应 |
| 引入：呈现与构建，5 | `godot-ui-control`、`godot-animation`、`godot-audio`、`godot-shaders`、`godot-export` | HUD、序列帧、声音、二维材质和原生包，按实际任务读取 |
| 引入：通用实践，3 | `level-design`、`game-feel`、`performance-optimization` | 通路与节奏、事件反馈、测量后优化；项目适配覆盖模板默认值 |
| 暂缓：需先解决示例问题，1 | `godot-signals-groups` | 超时示例不实现超时；基础信号语法已有覆盖，收益不足以增加这一指导来源 |
| 暂缓：移动／物理／地图重构，3 | `godot-2d-movement`、`godot-physics`、`godot-tilemap` | 原生物理和瓦片方案并非当前规则裁决及正式地图的实现；专项需求时再评估 |
| 当前不采用：Godot 其他方向，3 | `godot-3d-essentials`、`godot-csharp`、`godot-multiplayer` | 与原生 2D、GDScript、离线单机不匹配 |
| 暂缓：与已有路线／本批重叠，5 | `create-game-assets`、`audio-design`、`shader-programming`、`game-ui-ux`、`camera-systems` | 素材已有 Sprite Forge；其他专项先用原生实现技能，独立设计／镜头任务出现后再选 |
| 暂缓：后续功能与输入设计，6 | `game-ai`、`ai-behavior-trees-utility-ai`、`procedural-gen`、`dialogue-systems`、`save-systems`、`input-systems` | 以后续 Boss／随机房间／剧情／存档／输入规格为入口；不替换当前影偶规则或扩展输入合同 |
| 暂缓：物理调校，1 | `physics-tuning` | 当前自有规则需要先保持行为；只有明确物理问题／迁移任务才重新审查 |
| 当前不采用：其他引擎，30 | Unity 8、Unreal 6、Web 6、其他引擎 10 | 不因保留旧工程而路由到 Phaser；不新增多引擎指导 |
| 当前不采用：类型模板，9 | `platformer`、`roguelike`、`rpg`、`fps-shooter`、`tower-defense`、`card-game`、`visual-novel`、`survival-crafting`、`puzzle` | 类型标签不能替代九鼎玩法合同；尤其 `roguelike` 正文以回合格子为适用范围，不适合实时动作循环 |
| 暂缓：工作流，4 | `game-jam`、`prototype-fast`、`steam-publish`、`itch-publish` | 当前非比赛或渠道发布任务；工程流程已有 Matt 技能，独立原型／发布时再审读采用 |

上游 [router](https://github.com/gamedev-skills/awesome-gamedev-agent-skills/blob/0a70cfc64672d512c5b5b6006b5dcb5cf90dbdbd/router/SKILL.md) 不计入 74 项。它识别多引擎并组合技能，假定可以访问全目录；本项目保留旧 Phaser 文件且只安装子集，采用 AGENTS→使用指南→所选技能的明确路径更直接。没有复制另一份 router，也没有修改用户级 Matt 技能。

## 原文审读的具体发现

下列是固定提交中的源代码／文档发现，不推断上游全部配方均已正确：

| 来源 | 发现 | 本项目处理 |
| --- | --- | --- |
| [signals 参考](https://github.com/gamedev-skills/awesome-gamedev-agent-skills/blob/0a70cfc64672d512c5b5b6006b5dcb5cf90dbdbd/skills/godot/godot-signals-groups/references/signal-patterns.md) | `wait_for_signal_or_timeout` 创建 timer，但只 `await Signal(obj, sig)`，未监听 timeout | 首批不安装；未触发信号时，创建计时器本身不能结束等待 |
| [game-feel 正文](https://github.com/gamedev-skills/awesome-gamedev-agent-skills/blob/0a70cfc64672d512c5b5b6006b5dcb5cf90dbdbd/skills/disciplines/game-feel/SKILL.md) | hit-stop 写全局 `Engine.time_scale` 后固定恢复 `1.0`，没有原值和重叠管理 | 只引入其事件分层与反馈方法；全局停顿不直接复制。输入缓存／击退等涉及规则的内容以项目合同为准 |
| [动画参考](https://github.com/gamedev-skills/awesome-gamedev-agent-skills/blob/0a70cfc64672d512c5b5b6006b5dcb5cf90dbdbd/skills/godot/godot-animation/references/animation-tree-and-tween.md) | 方法轨建议在攻击帧产生 hitbox | 九鼎继续由规则裁决时序，动画读取状态；不产生第二份命中判定 |
| [导出参考](https://github.com/gamedev-skills/awesome-gamedev-agent-skills/blob/0a70cfc64672d512c5b5b6006b5dcb5cf90dbdbd/skills/godot/godot-export/references/presets-and-cli.md) | `--quit-after <frames|seconds>` 与正文主循环次数说法不一致 | 本机 `--help` 复核为 iterations，不用于墙钟采样 |
| [性能参考](https://github.com/gamedev-skills/awesome-gamedev-agent-skills/blob/0a70cfc64672d512c5b5b6006b5dcb5cf90dbdbd/skills/disciplines/performance-optimization/references/profiling-and-budgets.md) | `Performance.TIME_PROCESS` 被标为 process ms；另有池化、预算通用配方 | [官方文档](https://docs.godotengine.org/en/stable/classes/class_performance.html#class-performance-constant-time-process)说明为秒，换算后记录；先测量，按瓶颈采用，不先建池和预算系统 |

这些差异保存在项目使用指南，上游技能原文保持一致，便于更新对比。通用示例仍需在真实任务中校核局部／全局坐标、暂停、对象生命周期、单位及渲染器兼容。

## 验证与完成边界

本次对上游临时检出运行原 validator，通过 75 个技能文件及仓库连接检查（含 router）。安装目录另检查元数据、文件清单、SHA-256 与内部参考路径；在项目锁定引擎上，用独立临时工程运行上游 headless runner 的通过、故意失败及异步计时器示例。详细结果见 [verification.json](../../tools/gamedev_skills/verification.json)。

任务路由采用人工情景走查：类型修复→GDScript，暂停布局→UI，分层播放→动画，通路审查→关卡，反馈候选→game-feel＋动画，回归→headless，已有采样→性能。它验证指引清晰性，不是多个 Agent 的自动触发成功率实验。

没有修改游戏代码、资产、依赖或导出预设，因此未运行完整游戏导入／规则／导出检查。没有打开窗口、发送系统键鼠、播放音频或开展性能采样；没有证明这些技能已改善成品画面、手感、帧率或 Windows 兼容。后续每次使用记录所选技能、具体任务、返工问题及实际验收；收益不足或带偏时停用单项。
